**Orchestration ideas from them**

- [ ] Task and dispatch ids on every task and report, so a stale or retried worker's report can't complete the wrong task (Orca); optional dependencies between tasks.
- [ ] CI failures and PR review comments go back to the worker that owns the branch, without the root relaying them (Orca, Orchestrator.inc).
- [ ] Agent profiles with "when to use" notes, which the root reads to pick kind, model and effort beyond size (Paseo).
- [ ] Permission prompts, the rest: agy's, OpenCode's and Copilot's prompts reach the root the same way (agy runs under `--dangerously-skip-permissions`, so only when a user turns `skip_permissions` off); a fixture of a real `PermissionRequest` payload from `scripts/capture-claude-hooks.sh`, run by hand on a real account, to replace the documented shape the decoder and tests follow, and to confirm there that Claude shows its own dialog while the hook is held (if it does not, the person at the terminal waits up to `permission.wait`) and that a `PostToolUse` carries the same `tool_input` as the prompt (the daemon ends a prompt by tool and command); `neverForward` (outward commands, writes outside the worktree) only reads a Bash command and the file tools' path: a write by a shell command, or a path through a symlink, is still the root's to judge.
- [ ] Flaky `t.TempDir` cleanup ("directory not empty" in the state dir) in `TestTheSetupAgentsReminderIsSilentWhileItsResetTypes` (about 1 run in 40 under `-race`, also on a clean `origin/main`) and once in `TestOpenCodePollOnlyAdvancesLastOutputOnSuccess`: a daemon goroutine still writes into the state dir when the test ends; make the tests (or `Daemon.Close`) wait for it.
- [ ] agy login: an agy worker whose own terminal asks for a login (the probe never does) isn't told to the root until its turn fails; the `[mesh alert login agy]` covers the probe only.
- [ ] Schedules: start a worker on a cron or an event (Paseo schedules, Orca automations).
- [ ] Plan in Claude's real Plan mode instead of the planning deny list (design §9, line "Planning is enforced"; designed 2026-11-26, not built). It lost because leaving Plan mode was a dialog in the pane only a human could answer, and the plan went to Claude Code's own file; the `PermissionRequest` hook held for the parent (README, "Permission prompts") is the transport that was missing. Design: launch a Claude planner with `--permission-mode plan`; its `ExitPlanMode` arrives as a `PermissionRequest` (`tool_input.plan`, `planFilePath`); the hook copies the plan to `$(mesh dir)/plans/`, sends it to the root as a `plan` message and waits; `mesh approve` answers allow (the hook returns `updatedInput` = the tool input, and `updatedPermissions` to leave plan mode), a `changes` answer returns deny with its text, so the worker keeps planning in the same conversation; the model and effort swap stays with `mesh approve`'s reopen, which has to land while the old process's hook is blocked. Why it waits: (a) it changes the enforcement of every Claude planner (agy, OpenCode and Copilot keep their deny list or prompt, so two mechanisms live side by side); (b) the approve-then-reopen ordering with a blocked hook; (c) the `ExitPlanMode` payload, the plan-file injection and `updatedPermissions` need fixtures captured by hand on a real account (`scripts/capture-claude-hooks.sh`); (d) the plan the root reads would be Claude's file, not the worker's own write-up. Paseo shows it works when an agent can answer (its root approves `ExitPlanMode` with `respond_to_permission`, or denies it with a message).
- [ ] Research: compact a conversation before it's closed (retire, stop), while its cache is still warm, instead of only on resume (`maybe_compact`, design §12). A compaction on a warm cache reads the context at the cache-read price; on resume after the cache expired, the compaction or the reopen pays for it all again. Find out from our session data (`mesh cost`, `docs/cost-research/`) how often closed conversations are resumed and how long after, at what size, for which kinds (workers, peers, reviewers, roots), and what each policy would have cost; ask the peers how they handle it.
- [ ] Branch names, commit messages and PR text from a small model (Haiku class) instead of the worker's (Paseo's metadata generation).
