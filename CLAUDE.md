# CLAUDE.md / AGENTS.md

Guidance for Claude Code and Antigravity (agy) agents working in this repository.

agent-mesh lets an agent working in repo A hand repo B's part of a change to an agent running *inside* B (with B's `CLAUDE.md`/`AGENTS.md`, skills and hooks loaded), in a visible herdr pane with two-way messaging. `README.md` is the user-facing pitch and `docs/guide.md` the full reference; `docs/design.md` records why each decision was made and the alternatives that lost: read its section before changing behaviour. `docs/apps.md` is the plan for the daemon and apps that replace herdr and refactor agent-mesh: for that new code it overrides `docs/design.md` and the conventions below where they disagree (workers may start read-only agents, for one).

## Task tracking

Open work is tracked in `TODO.md` as deliberately short summaries: the agent doing a task works out the details. Check it before starting something that might already be tracked, and keep it current in the same change: remove (or tick) a task when the work lands, reword it when scope changes, and add a line for any follow-up you find but don't do.

## Commands

```bash
uvx pytest -q tests                              # full suite
uvx pytest -q tests -k approve                   # tests matching a name
uvx pytest -q tests/test_mesh.py::test_name      # one test
./install.sh            # symlink into place (--uninstall reverses it); safe to re-run
```

To try `bin/mesh` by hand, point `MESH_HOME`, `MESH_WORKTREES` and `MESH_PEERS_DIR` at temp dirs, `MESH_CONFIG_FILE` at a temp file, `MESH_HERDR` at a missing binary and `MESH_CLAUDE` at one that does nothing (`/bin/false`: a missing one makes Claude count as not installed), as `tests/conftest.py` does, because the defaults are the real run state and herdr panes every agent uses. A worker that forgets is refused every command but its own (`check_worker`).

`bin/mesh` has no build or lint step: it is one Python 3.10+ script with no dependencies. Keep it stdlib-only. The apps' commands are in their rules files (below).

The installed `mesh`, `~/.config/agent-mesh` and the skills are **symlinks to this checkout**: every agent on the machine runs whatever branch is checked out.

## Layout and how the pieces fit

- `bin/mesh`: the whole CLI (argparse in the `# ── CLI` section, one `cmd_*` per subcommand), in sections marked with `# ── name ──` comments: paths, run state, identity, herdr topology, models, sessions, worktrees, messaging, commands, past workers.
- `protocol/`: Markdown the agents follow, installed as `~/.config/agent-mesh`: `ORCHESTRATE.md` the root/worker procedure (and the mode table), `PROTOCOL.md` the messaging rules every mesh agent reads, `PLAN_TEMPLATE.md` the plan format. Agents orchestrate by following these files, not code, so a behaviour change usually needs a `bin/mesh` change and a protocol/doc change.
- `skills/delegate-agy`, `skills/delegate-claude`: the `/delegate-*` entry points, typed by the user or invoked by an agent (never a worker) when a request fits; they point the root at `ORCHESTRATE.md`.
- `skills/delegate-review`: a PR review the user asks for, by any mix of Claude, agy and Copilot (or `all`), run as one review round (`mesh ask --reviewers`). It reads only ORCHESTRATE's "Questions and reviews".
- `skills/find-peers`: finds projects that share a repo's core mechanisms, ranks them by overlap, and on the user's yes registers them as peers (`mesh peers add`), unbriefed. Root only, any repo.
- `skills/harvest-peers`: a research round by the peers (first brief or follow-up from `HARVEST.md`, with bug-hunt targets), every finding checked in our code, survivors filed in the tracker on the user's yes. Root only; never run by `find-peers`.
- `skills/make-concise`: rewrites a repo's rules files concisely without dropping a rule, run by that repo's own agent; `validate.py` (stdlib, tested in `tests/test_make_concise.py`) fails on a lost fence, marked block, code span, URL, path or `@` import, or a file over 24,000 bytes.
- `skills/self-review`: a worker's review of its own PR before `done` (Claude: `/code-review`).
- `skills/check-plan`: a worker's self-check of its draft plan (ORCHESTRATE Worker step 4): verify its claims in the code, attack it, fix it. It edits only the plan file, so it runs under the planning deny list; usable by hand in any session.
- `.claude-plugin/`: the repo as a Claude Code marketplace of one plugin (`source: "./"`) that ships `skills/`; no `version`, so users track commits. Skills only: the CLI and `~/.config/agent-mesh` still need `install.sh` (which skips the `~/.claude/skills` links when the plugin is installed, or with `--plugin`). `tests/test_plugin.py` checks it ships exactly `SKILLS` (design §16).
- `rules/global-snippet.md`: the block `install.sh` writes between markers into `~/.claude/CLAUDE.md`, `~/.gemini/AGENTS.md`, `~/.copilot/copilot-instructions.md` and (unless it would hide `~/.claude/CLAUDE.md` from OpenCode) `~/.config/opencode/AGENTS.md`.
- `herdr/mesh-notify`: a herdr plugin (`install.sh` links it) that notifies the desktop when a root or a plain session is `done` or `blocked`, never a worker, and a root's `done` only once no worker owes it a report (design §20). It reads `run.json` and `log.jsonl` directly and mirrors `RECEIVED_TYPES` / `REPORT_TYPES` (`tests/test_notify.py` checks they match).
- `.claude/settings.json`: a `PreToolUse` tripwire (`.claude/hooks/guard_generated.py`, tested in `tests/test_project_claude.py`) that stops every Claude agent here from editing generated code with its editing tools; a shell write passes it, and the check scripts are the backstop.
- The parts of `docs/apps.md` each have a rules file (commands, layout, conventions); read it before working there:
  - `daemon/CLAUDE.md`: the Go daemon and relay, not live yet.
  - `proto/CLAUDE.md`: the API, and the clients a schema change regenerates.
  - `desktop/CLAUDE.md`: the Electron app.
  - `android/CLAUDE.md`: the Kotlin app.

Core mechanics of `bin/mesh` that span several files: each bullet is the gist and the names to start from. `docs/design.md` has the why (by section) and, in "Code map", each one's functions. Change a mechanism, update both.

- **CLI adapters** (design §22): what differs per CLI (binary, process names, models, launch/resume/deny argv, session lookup, limits, quotas, cost, capabilities) lives in one `Cli` subclass per kind in `CLIS`; generic code asks `cli(kind)` / `cli_has(kind, flag)` instead of comparing kind names; `KINDS` / `ASK_KINDS` derive from it. A new CLI is a new adapter (tests in `tests/test_kinds.py`).
- **Run state** lives in `$MESH_HOME/<run>/` (default `~/.local/state/agent-mesh`): `run.json` (agents, models history, worktrees), per-agent mailboxes, `log.jsonl` events, and the `RUN_FOLDERS` agents write into (`plans/`, `reports/`, `tasks/`). Mutate it only through `editing_run(run_id)` (locked, atomic; `editing_run(run_id, folder)` for an archived run).
- **Mailbox plus doorbell** (design §3): `mesh send` writes the message file first, then `deliver` types a one-line `📬 [mesh]` doorbell into the recipient's pane via `herdr agent prompt` (`ring_stored`), retrying until its fresh `(ref <token>)` shows above the input box, and never into a human's draft (`human_draft`, per-pane `ring_lock`). A lost doorbell loses nothing. `main` runs `check_worker` first: a worker of a live run runs only `WORKER_COMMANDS` and sends only to its parent (design §10).
- **Native transport** (design §11): `mesh` writes a Claude recipient's doorbell straight into its inbox socket (`write_inbox`), when `native_route` finds one that accepts it: a worker launched accepting cross-session messages (`worker_settings`: `crossSessionInbound: accept`), or a root taking unattested frames (`inbound_setting`). `send_message` (the sender's `SendMessage`, backed by the Stop hook and `Watch.lost_report`) serves a Claude sender reaching a bypass-mode root or a pre-flag background worker; else the pane rings. A Claude pane worker relaunched outside mesh (a herdr restore) is reopened with its deny list before any doorbell (`reopen_relaunched`). The mailbox is the record either way.
- **Views and sizes** (design §9, §11): a worker runs in a herdr pane or as a `claude --bg` session (`view`); `SIZE_VIEWS` maps (kind, size) to a view (model and effort come from the root's tier); trivial and small tasks skip the plan phase (`DIRECT_PREFIX`), `large` plans first. A `--bg` session never sees the launch environment, so `launch_bg` passes identity and config as `--settings` env (`worker_settings`); every `claude` call runs on `claude_env()`. Read-only, peer, small and planning workers get `promptCacheTtl: "5m"` (`worker_cache_ttl`).
- **Identity** (design §4) comes from `MESH_RUN` / `MESH_SELF` / `MESH_PARENT` / `MESH_ROLE`, injected at spawn. `inherited_identity` drops one that isn't this agent's: a Claude worker owns its pane only while its `CLAUDE_PID` leads the pane's process group, and `pane_worker` finds one a herdr restore relaunched without `MESH_*`. Agents are addressed by herdr name (`<repo>-lead`, `<repo>-<slug>`), with pane id as fallback.
- **Topology:** a root supervises one worker per repo, its own included, each in a git worktree under `$MESH_WORKTREES` on branch `mesh/<run>/<slug>`. Workers never spawn agents (1:N, not 1:N:N; design §7).
- **Policy** (design §21): every knob (`mesh routing` lists them: tiers `tiers.<kind>.<tier>.*`, views, reviewer slots, rounds, `quota_stop`, folders, `skip_permissions`, thresholds, `compact.*`, `root_reset.*`, `claude.*`) is a `POLICY` leaf, read with `setting()` (env > `~/.config/agent-mesh.json` or `MESH_CONFIG_FILE` > built-in; never the constants directly). Docs name the leaves, not their values. `installed` / `require_cli` keep mesh off a CLI not on PATH; `pick_reviewers` fills the slots from available ones. The `mesh` fixture points `MESH_CONFIG_FILE` at `tmp_path` and makes every CLI look installed (`with_config` and `clis` in `conftest.py` change that).
- **Models per phase** (design §9): the root picks a tier for every start; no default (`need_tier`). A large task's execution tier comes at `mesh approve --tier` (`swap_model` reopens **the same conversation**); `mesh switch --effort` / `--tier` later. `tier_chain`, `plan_model`, `entry_chain`; `--why` is recorded. `mesh models` flags unplaced families. `mesh watch` exits 7 on a quota error: the root runs `mesh switch`. The quota reserve (`reserve_guard`, `quota_stop`, `claude_usage`, `reserve_alert`) refuses new work on a vendor once a quota is `MESH_QUOTA_STOP`% used, until `mesh reserve off`.
- **Questions and reviews** (`mesh ask`, design §10): an asker is an ordinary worker with a read-only task (`ASK_PREFIX` / `REVIEW_PREFIX`), so follow-ups and resume need no special case; `cmd_ask` composes `init_run`, `reach_worker`, `deliver` and `watch_agent`. A review is of one commit (`review_heads`); a Claude reviewer runs `/code-review` on it at the review's size (`REVIEW_LEVEL`, `head_diff`). A Claude worker that is `read_only` or `planning` runs under `claude_deny`'s `--disallowedTools`; `swap_model(..., lift=True)` (on approve) reopens it without.
- **Review rounds** (design §10): after the author's self-review, `ask --repo --review --tier --reviewers auto|all|<kinds>` (`ask_reviewers`, `review_round`) runs a PR's reviewers at once, chosen by size, tier, quota and not the author's CLI (`pick_reviewers`, `pr_author_kind`), on `ask --peers`'s collect path (`watch_each`, `write_answers`): one `reports/review-<n>-<stamp>.md`, one root wake. After a fix it re-asks the same reviewers minus Copilot (`--since <head>`: only the fix commits); `review.rounds.<size>` is a ceiling (`rounds_hint`). `mesh verdict`: the root's verdict per reviewer, summed in `mesh cost`.
- **OpenCode workers** (design §22): `OpenCodeCli` on OpenCode's free models (`free`) or any provider it reaches; per-launch config is in the pane's env (`launch_env`: an agent per model and effort, `OPENCODE_PERMISSION` when read-only), and its session is found in its db by the first doorbell; a model at its limit is exit 7 (`quota_hit`, held in `model-limits.json`) and `mesh switch` rotates to the next model of the chain.
- **Copilot workers** (design §22): a pane worker like the others (`CopilotCli`): `--session-id` chosen at spawn, `--deny-tool` while read-only or planning, no Stop hook (the watch nudges it), its rate-limit screens and 402 quota error as exit-7 limits. Input-box ghost text is read per CLI (`ghost_styles`).
- **Peers** (design §14): `$MESH_HOME/peers.json` (`load_peers`, `editing_peers`) registers standing read-only askers, one per cloned project, in detached worktrees `mesh stop` never removes (`ensure_peer_worktree`). Every ask runs `prepare_peer`; `ask --peers` (`ask_peers`) reaches them in threads, waits with `watch_each` and writes one `reports/peers-<stamp>.md`.
- **Resume onto a finished PR** (design §8): `leave_finished_pr` moves a change task's worktree to a new `mesh/<run>/<slug>` when no PR from its branch is open (`finished_pr`).
- **Compaction on resume** (design §12): `maybe_compact` runs `/compact <focus>` headless on the stopped conversation before `resume_worker` reopens it, when `should_compact` says so (`compact.claude`, `compact.claude_cold` once `cache_cold`, `compact.agy`); `approve_compaction` and `followup_compaction` compact live ones.
- **Root reset** (design §15): root commands print `root_hint` when the root is big and cold (`root_context`, `root_reset.at`). `mesh reset` starts a detached `reset_root`, which at a quiet input box relaunches the root lean (`relaunch_root`; else `/clear`) and rings `bootstrap_text`. The root keeper runs `maybe_autoreset` (quiet 5 min after a mesh turn, 30 after a user's). `mesh brief` prints `protocol/ROOT_CARD.md`; `mesh protocol <part>` reads one.
- **Lean sessions** (design §11): Claude agents start without unused tools, skills, plugins & MCP (`claude_launch_argv`, `lean_settings`, `claude.*`); `mesh tools add` reopens the same conversation with one (`tools_reopen`); the root passes servers per task (`--mcp`, `mcp_lease`). context7 and WebSearch/WebFetch reach every agent.
- **Worker hooks** (design, "The Stop hook"): every Claude worker launch passes `worker_hooks` in `--settings`. `Stop` runs `mesh hook stop` (`stop_hook`: blocks once per task with no report, `claim_nudge`, on unread mail, `hook_mail`, and on a `SendMessage` owed; always exit 0); `SessionStart` runs `mesh whoami --reminder <source>`. Both outputs go through `hook_text` (under `HOOK_OUTPUT_MAX`, no wall-clock text).
- **Derived status** (design §13): `mesh status` recomputes what each worker owes or waits on at every call (`waiting_rows`), needing-the-root first; none of it is stored. `read_log` skips a torn line and `log_event` seals one before appending.
- **Watchdog:** `watch_agents` polls one `Watch` per worker (`mesh watch <name>`, or `--any` with a `Roster`). A worker idle with no report since its last task/answer (`since_last_task`) gets one `nudge`, then exit 3/4; 7 is a usage limit, quota or login (`limited`), 8 a hang (`HANG_AFTER`), 0 a stopped run. A declared `wait` (`declared_wait`) pauses idle counting. A worker at a limit no switch fixes gets `continue` at the reset (`schedule_continue`, design §9). `mesh watch`, or the run's retirer a `done`/`failed` starts (`ensure_retirer`), retires a worker idle `idle_retire` after it (`Watch.maybe_retire`; not while the user is attached or its pane focused: `viewer`). A `send` (task/answer/question; an `info` is only stored, exit 2; a retired peer is refused) or `ask` to a retired worker resumes it (`resume_stored`, design §18). `agent_status` checks herdr against the process table; git reads run on `git_env()` (never the worker's index lock).
- **Resource guards** (design §17): `memory_guard` refuses a new agent (the last check before `start_worker`'s and `reopen_worker`'s side effects) under `min_free_mb` (`MESH_MEMINFO`) or over `memory_pressure_max` (`memory_pressure`, `MESH_PRESSURE`), counting the machine-wide `reservations.json` of agents still starting; `sweep_worktrees` (on retire and stop) TERMs then KILLs orphan trees in a worker's worktree holding no terminal or agent. `confine_agent` pins each launched agent to the least-held `cpu_window` (`worker_cpus`) and, with `worker_memory_high`, a systemd `memory_scope` (tests read `mesh.pins`).
- **Spend** (`mesh cost`, design §19): `run_cost` reads Claude session files (folded by `message.id`) and agy steps, places each call on a run's agent by time (`cost_segments`; a root counts only while its run is open) and prices it (`PRICES`) per agent, kind and phase, with cold resumes; `--since`/`--until` covers every session in a window.
- **Conversation lookup** (`find_session`): Claude workers get a `--session-id` recorded at spawn; agy conversations are found in `conversation_summaries.db`, then `history.jsonl`, by the first doorbell text (`You are <name> (worker) in agent-mesh run <run>`), and recorded on the worker's first `mesh send`. Changing that doorbell wording breaks resume.

## Conventions the design depends on

- Model changes happen only by reopening the same conversation (approve / switch / resume), never by briefing a fresh worker, so the worker keeps its research context. Reject designs that add delegation tiers or cold hand-offs.
- The mesh is process-agnostic: protocol files never name a tracker, branch convention or repo-specific process; workers follow their repo's own rules.
- Skills name model **families** (`argon`, `hydrogen`, `flash`, `opus`, `sonnet`), resolved to the newest id from `agy models`; don't hard-code model ids.
- `mesh resume` / `mesh open` refuse a worker that is still running (one process per conversation); `open` attaches to a running background worker instead. `mesh stop` stops background workers (never `claude rm`), removes only clean worktrees and keeps every branch that has a commit or an upstream (an untouched one is deleted and recreated from its recorded `base` on resume).
- Re-run `./install.sh` once a change that needs it is on the checked-out branch (merged to `main`): a change to `rules/global-snippet.md` (it is copied into `~/.claude/CLAUDE.md` and `~/.gemini/AGENTS.md`, not linked), a skill added, removed or renamed (update `SKILLS` / `RETIRED_SKILLS` and the plugin's description in `.claude-plugin/marketplace.json`), the herdr plugin moved, or `install.sh` itself changed. An edit inside a linked file (`bin/mesh`, `protocol/`, a skill) needs no re-run.
- Keep README, `docs/guide.md`, `ORCHESTRATE.md`, the skill descriptions and `docs/design.md` in sync when defaults (models, efforts, exit codes) change.
- Keep each rules file (this one and the four above) at most 24,000 bytes, because agy truncates a rule file past that, each with an `AGENTS.md` symlink to it beside it (`tests/test_docs.py` checks both). Put detail in `docs/design.md` (function names in its "Code map") and a gist here.
- A change that alters a part's commands, layout or conventions updates that part's rules file (this one for `bin/mesh` and the repo) in the same PR.

## Tests

`tests/conftest.py` loads `bin/mesh` as a module (`mesh` fixture), points `MESH_HOME`/`MESH_WORKTREES` at `tmp_path`, and replaces `mesh.herdr` with `FakeHerdr` (`fake` fixture): register answers with `fake.on("agent", "get", result=...)` / `error=...`, assert with `fake.called(...)`; `fake.screen(target, text, …)` is what `herdr agent read` prints (one text per read, the last repeated). The `run` fixture is an initialised run `mtest` with root pane `w1:p1` and a worker `repo-fix-typo`. Worktree tests use real repos. Tests must never run real `agy`, `claude` or `copilot`: the `mesh` fixture replaces `run_cli` with `FakeCli` (the `cli` fixture: `cli.on("--bg", stdout=…)`, `cli.called("stop", id)`; each call records `argv`, `cwd`, `env` and `input`), points `MESH_HERDR` at a missing binary, makes `subprocess.Popen` refuse `agy`, `claude`, `copilot` and `herdr` (`RefuseAgentClis`) so a path bypassing the fakes fails, and points `MESH_CC_SOCKS` at an empty folder (`claude_root(mesh, run)` gives the root a socket; the `inbox` fixture binds real ones). For quotas use `with_quotas(mesh, monkeypatch)`, which seeds the `agy models` cache from the `AGY_MODELS` fixture (made-up ids like `gemini-3.10-flash`, to test version ordering) and stubs `agy_usage`.
