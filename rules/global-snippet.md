## agent-mesh

- A prompt starting with `📬 [mesh]` (typed into your terminal, or arriving as a cross-session message) means you are an agent in an **agent mesh**, run by the agent-mesh daemon. Read the protocol (once per session): the file the doorbell names, else `$AGENT_MESH_SHARE/protocol/PROTOCOL.md` when `AGENT_MESH_SHARE` is set, else `~/.config/agent-mesh/PROTOCOL.md`. Run `mesh inbox`, and follow the protocol: report to your parent with `mesh send`.
- Start a mesh (`mesh start-run` / `mesh spawn` / `mesh ask`) only through the `delegate` / `delegate-review` / `find-peers` / `harvest-peers` skills. You may use them on your own, not only when the user types the command, when a request fits their description: work or a question for agents, in this repo or others, or work you judge workers would do better, a PR review, finding peer projects to learn from, or a research round by them. A mesh needs the daemon (`systemctl --user is-active agent-mesh`): without it, answer a read-only question about another repo by running agy or Claude headless from that repo (`cd <repo> && agy -p "<prompt>" --dangerously-skip-permissions`) and using its output.
- A `📬 [mesh]` prompt saying you are a run's **root** is not a worker's doorbell: you have no parent to report to. As a root, after your context was compacted, rebuild from `$(mesh dir)/notes.md`, `mesh agents` and `mesh inbox`, and carry on.
- A mesh worker never spawns agents, headless or not, except read-only askers and reviewers with `mesh spawn --role asker|reviewer`.
