# daemon/: rules for agents

The Go daemon (`meshd`), its terminal host (`mesh-term`), the generated CLI (`mesh`, built from `cmd/mesh`) and the stream relay (`mesh-relay`), step 1 and 3 of `docs/apps.md`. `./install.sh` installs it (`README.md`, "Installing"). `README.md` is the full reference (layout, behaviour, protocol notes) and `docs/apps.md` the plan; for this code `docs/apps.md` overrides `docs/design.md` (the record of the retired `bin/mesh`) where they disagree (here a worker may start read-only agents, for one). The API is in `../proto/` (read `proto/CLAUDE.md` before changing it). context7 and WebSearch/WebFetch are available to every agent: check a library's current API there (ConnectRPC, the SQLite driver, `charmbracelet/x/vt`) rather than from memory.

## Toolchain

Off PATH on this machine: Go in `~/.local/go`, buf in `~/.local/opt/buf/bin`, and `~/.local/opt/zigcc/cc` (a `zig cc` wrapper) as the C compiler `go test -race` needs. `scripts/check.sh` finds them itself; for anything else run `export PATH="$PATH:$HOME/.local/go/bin:$HOME/.local/opt/buf/bin"` first. The code generators are pinned as `tool` directives in `go.mod`, so `buf generate` installs nothing.

An agent's shell carries `AGENT_MESH_TOKEN` and `AGENT_MESH_STATE`: `check.sh` unsets every `AGENT_MESH_*`, and the daemon and e2e `TestMain`s call `testutil/cleanenv`, so a hand-run `go test` works too.

## Commands

```bash
daemon/scripts/check.sh                      # the CI equivalent: buf lint and breaking, gen current, gofmt, vet, test -race, pytest
SKIP_PYTEST=1 daemon/scripts/check.sh        # without the Python suite
cd daemon && go test ./...                   # the Go tests only
cd daemon && go test ./internal/daemon -run TestName   # one package, one test
cd daemon && gofmt -w cmd internal e2e       # check.sh fails on unformatted code
cd daemon && go test ./internal/registry -update       # accept a reviewed change of who may call what
cd daemon && go build -o bin/ ./cmd/...      # binaries into daemon/bin/ (gitignored)
cd daemon && go build -tags ts_omit_logtail,ts_omit_peerapiserver -o bin/ ./cmd/...   # as install.sh does; meshd --tailscale refuses a build without them
```

Run `check.sh` before you report a change here: the repo runs no hosted CI, so it is the gate.

## Layout

`cmd/` holds the four binaries (and `protoc-gen-flagdocs`, a build-time buf plugin, not shipped); `internal/` one package per concern (`daemon` the server and handlers including `cost.go`/`models.go`/`conflicts.go`/`prs.go` (PRs per agent)/`prfeedback.go` (their CI and review feedback, told to the owning worker)/`held.go` (tasks held until another task is reported done)/`evidence.go` (what an alert adds)/`worktree.go`/`log.go`/`ring.go`/`open.go`, `registry` who may call what, `store` SQLite and migrations, `settings` the settings table, `events`, `termhost`/`termclient`, `adapter/claude`, `adapter/agy`, `adapter/opencode` and `adapter/copilot`, `inputbox` (what an agent's input box holds, read from a repaint), `transcript` (what the adapters share to read a conversation for the chat view: the JSONL pager, the cuts), `shellmatch`, `reducer`, `hook`, `relay`, `pairing`, `tlsutil`, `tailnet` (the tsnet node; only it and `cmd/meshd` import tsnet), `probe` (runs a CLI the daemon asks a question of so it can never open a login), `auth`, `cli` including `cli/open.go`, `repoarg` (what a `--repo` argument is), `notice` (the kinds, tabs and brief text of a notice: `daemon/notify.go` decides which events make one) and `webpush` (RFC 8291 encryption and the POST; `daemon/push.go` sends)); `gen/` the generated Go; `e2e/` the end-to-end test of the real binaries; `packaging/` the systemd units and the relay's container. `share/` the protocol and skills daemon agents read (`README.md`, "Protocol and skills"). `README.md` "Layout" maps every package.

## Conventions

- **Generated code:** never edit `gen/` by hand; change the `.proto` and regenerate (`cd proto && buf generate`; it also writes each package's `FieldDocs`, the field comments `mesh help` shows, by `cmd/protoc-gen-flagdocs`). `check.sh` fails when it is stale.
- **Who may call what** is pinned by `internal/registry/testdata/actors.golden`. Update it only with `-update` after reading its diff: a changed line changes an actor class's rights.
- **State dirs:** a dev or test meshd always gets a temp state dir of its own (meshd has no default, so it can't land in a real one). Keep the path short: a unix socket path holds about 107 bytes, and meshd refuses a longer one. A test makes its state dir (and any dir a unix socket lives in) with `internal/testutil/shortdir` (`State(t)`, `New(t)`, `Make`), a short name under `/tmp`, never `t.TempDir()` (it carries the test's name, and with a long `TMPDIR` the socket path passes the limit); the suite passes with any `TMPDIR`. `check.sh` makes scratch dirs of its own (`TMPDIR` and `GOTMPDIR` under the caller's `TMPDIR`, else `/var/tmp`: on disk, not on the shared `/tmp` tmpfs; and a short one in `/tmp` named by `MESH_TEST_SHORT_TMP`, which `shortdir` follows) and removes them when it ends, also on a TERM or INT (it runs `go test` and pytest as a job it kills with its group), so a killed gate leaves nothing on the `/tmp` tmpfs; a hand-run `go test` that was killed leaves its dirs, and the daemon and e2e `TestMain`s remove the old ones (`shortdir.Sweep`, three hours: the dirs `shortdir.Make` made, which hold a marker file, and the built-binaries dirs).
- **Never run a real `agy` without its real HOME and token** (not in a test, not as a live check, not in a temp HOME, not under `strace`): a logged-out agy opens a Google login in the user's Windows browser under WSL, again at every run. Real agy is for `agy models` and `agy --help` with the real HOME only; the probe (`internal/probe`) and everything that runs agy is tested with `fakeagy`.
- **No real CLIs in tests:** tests run the fakes (`internal/testutil/fakeclaude`, `internal/testutil/fakeagy`, `internal/testutil/fakeopencode`, `internal/testutil/fakecopilot`) in an isolated HOME. `scripts/capture-claude-hooks.sh` and `scripts/capture-agy-hooks.sh` run the real CLI on the user's account: run them **by hand only**, never from a test or CI, and read the fixtures' diff before committing it. A live check of a CLI's behaviour (what its box, `/compact` or `/clear` really do) runs the same way, on a dev meshd of its own (`README.md`, "Live checks"), with `bin/screendump` to see a terminal's screen; a fake must follow what it showed (`FAKECLAUDE_BOUNDARY_DELAY`), and the check's findings go in that section.
- **Store migrations** are numbered, embedded SQL files (`internal/store/migrations/`, numbered 1, 2, … with no gaps). Add a new one for a schema change; never edit one that has shipped, because a host that already ran it won't run it again.
- **Settings:** a new policy knob is a leaf in `internal/settings/schema.go` (key, type, default, summary, choices, and the `Label` in sentence case, the `Group` of the settings screen and `Advanced` for the tuning most people never touch: `NewSchema` refuses a leaf without a label or a known group), read with `Daemon.Setting`; the settings screens are generated from it. A bin/mesh leaf gets its daemon key (or a stated skip) in `internal/settings/policyfile.go`, which `meshd --policy-file` and `mesh import-settings` use to carry `~/.config/agent-mesh.json` over once (`README.md`, "Settings"): the file is never read as a layer.
- **Path fields:** a request field holding a filesystem path (a repo, a local source) carries `(agentmesh.v1.path) = true` in its proto; the CLI makes it absolute against the caller's cwd and `~` before sending, because meshd's own cwd is not the caller's (`mesh ask --repo .`). Without the option a new path field breaks for relative values. A `repo` field that may also hold a bare name (looked up in `repos.dir`) adds `(agentmesh.v1.repo_name) = true`, and the daemon resolves it with `repoTop`.
- **Doorbells:** `internal/daemon/delivery.go` (README, "Doorbell delivery"): a message counts as delivered only once the agent took its doorbell (`ref` token, activity after the ring, read, or the token above the box), a doorbell is never typed into a human's draft (`ReadInputBox`), a retry never at a screen with no box (a first try does, as `bin/mesh` does), and a Claude agent's is written into its inbox socket (`DeliverNative`). One exception: an adopted root (`mesh adopt`) has no ring to follow, so its message counts as delivered once the frame is written, and a dropped frame is not rung again (`deliverAdopted`). Delivery tests use the fake claude's `FAKECLAUDE_BOX`, `FAKECLAUDE_DROP`, `FAKECLAUDE_STUCK`, `FAKECLAUDE_DIALOG` and `FAKECLAUDE_INBOX`.
- **Same conversation:** a model change reopens the agent's own conversation (`--resume`), never a fresh agent briefed again (root `CLAUDE.md`, "Conventions").
- **Relay:** `cmd/mesh-relay` speaks the protocol in `docs/relay.md`, deployed from `packaging/relay/`; keep it free of SQLite and the terminal host.
- **Tailnet:** tests never join a real tailnet: `internal/daemon` tests use a fake `daemon.Tailnet`, and `internal/tailnet`'s run Tailscale's `testcontrol` on 127.0.0.1 (`tailnet.New` refuses an empty control URL under test). Don't import tsnet outside `internal/tailnet` and `cmd/meshd`.
- **Background goroutines:** a goroutine that outlives its request and reads the store or writes the state dir starts with `d.goBG` and ends on `d.stopCtx()` (or the background context), so `close()` waits for it before it closes the store (it refuses new ones once it began: handle a `false`). A bare `go func()` is only for work joined within its request (a `WaitGroup`), a server's own listener goroutines, or a sender the pusher tracks. A test that builds a `Daemon` by hand waits with `t.Cleanup(d.bgWG.Wait)` before its store closes.
- **Docs:** `README.md` describes behaviour, so a change to behaviour updates it in the same PR, as it does this file when the commands, layout or conventions change.
