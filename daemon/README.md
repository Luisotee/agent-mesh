# daemon

The Go daemon that replaces herdr and the pane-handling parts of `bin/mesh` (`docs/apps.md`, "Order of work" step 1). It doesn't replace anything yet: the live mesh is still `bin/mesh`, and nothing here is installed or put on PATH.

## Layout

- `../proto/`: the API as protobuf. `agentmesh/v1` is the action registry (`MeshService`, each RPC with its allowed actor classes in the `action` option), `agentmesh/term/v1` the terminal host's API and WebSocket frames, `agentmesh/adapter/v1` the CLI-adapter plugin interface. `buf.yaml` and `buf.gen.yaml` live there.
- `gen/`: the generated Go code (committed; regenerate with `cd proto && buf generate`). Reviewers can skip it.
- `cmd/meshd`: the daemon (including optional `--listen` TLS and `--relay-url` outbound relay connector).
- `cmd/mesh-relay`: the self-hosted stream relay (`docs/relay.md`), static binary for VPS deployment (`packaging/relay/`, `packaging/systemd/agent-mesh-relay.service`).
- `internal/tlsutil`, `internal/pairing`, `internal/relay`: persistent ECDSA P-256 cert & SHA-256 fingerprint pinning, `agentmesh://pair` URI codec, and zero-trust relay server/connector/client.
- `internal/registry`: the action registry read from the descriptors; `testdata/actors.golden` pins what each actor class may call.
- `internal/auth`: tokens (stored as SHA-256), the interceptor that takes the actor from the token, and the browser refusal.
- `internal/store`: SQLite (pure Go, WAL), embedded numbered migrations, backed up before migrating.
- `internal/settings`: the host's settings table (`schema.go`): each leaf's key, type, default, summary and choices, and the check a value must pass.
- `internal/events`: the resumable event stream.
- `internal/daemon`: the server and its handlers (`agents.go`: spawning, hooks, adoption, doorbells, the terminal proxy); `internal/client`: how local callers dial it; `internal/statedir`: the state dir's files.
- `cmd/mesh-term`, `internal/termhost`: the terminal host. `internal/termclient`: the daemon's side of it (its API, terminal streams, starting it).
- `internal/adapter`: the CLI-adapter registry; `internal/adapter/claude`: Claude Code's adapter; `internal/adapter/agy`: Antigravity CLI's (`agy`) adapter. `internal/reducer`: the pure state reducer. `internal/hook` and `cmd/meshctl`: the hook command and its spool. `internal/proc`: pids checked by start time.
- `internal/testutil/fakeclaude`, `internal/testutil/fakeagy`: the fake CLIs the tests run (turns and hooks, no network).
- `packaging/systemd/`: the two user units for production (shipped, not installed).
- `cmd/meshctl`, `internal/cli`: the CLI, generated from the registry at run time.
- `e2e/`: the end-to-end test of the real binaries (`TestEndToEnd`).

## Toolchain

Go (see `go.mod`), [buf](https://buf.build) for the protos, and for `go test -race` a C compiler. The code generators are pinned as `tool` directives in `go.mod`, so `buf generate` installs nothing. On the dev machine they are user-local, off PATH: Go in `~/.local/go`, buf in `~/.local/opt/buf/bin`, and `~/.local/opt/zigcc/cc` (a `zig cc` wrapper) as the C compiler. `scripts/check.sh` finds them there.

## Commands

```bash
daemon/scripts/check.sh                      # the CI equivalent: buf lint and breaking, gen current, vet, test -race, pytest
cd daemon && go test ./...                   # the Go tests only
cd proto && buf generate                     # after changing a .proto
cd daemon && go test ./internal/registry -update   # accept a reviewed change of who may call what
cd daemon && go build -o bin/ ./cmd/...      # binaries into daemon/bin/ (gitignored)
```

## Running a dev instance

Always give it a state dir of its own: meshd has no default, so it can't land in a real one by accident. A unix socket path holds about 107 bytes, so keep the state dir path short: meshd refuses to start with a longer one.

```bash
state=$(mktemp -d)
daemon/bin/meshd --state "$state"            # socket at $state/meshd.sock, device token at $state/device.token
```

Every call needs a token. The host's own CLI uses the device token meshd writes on first start (`device.token`, mode 0600); each agent gets its own at spawn, in `AGENT_MESH_TOKEN`. The actor of every action comes from the token, never from the request. Requests that carry a browser's `Origin` or `Sec-Fetch-Site` header are refused, and `--tcp` binds loopback only. A token of an agent names its run and reads only that run; a token without one is not stored.

A run is one trust domain for events for now: every agent of a run receives its run's events, so a reviewer or asker sees the bodies of the `MessageSent` events between the run's other agents, though it can send only to its parent and children. `TODO.md` tracks revisiting it.

## meshctl

Every action of the registry is a `meshctl` command, built at run time from the compiled schemas: the command is the action's `cli` name, each request field is a flag (`snake_case` → `--kebab-case`; a bool is a switch, `--peek`; enums by short name, `--role worker`; message fields as JSON; `@file` or `@-` for text, `@@` for a literal leading `@`), `--json` gives the whole request (also before the command: `meshctl --json '{…}' set`) and the other flags override it (a repeated field's first flag replaces the list the JSON gave, the next ones add to it), a `google.protobuf.Value` field takes any JSON or, when the text isn't JSON, the string it spells (`--value sonnet`, `--value 75`, `--value '["haiku","sonnet"]'`), and the response prints as JSON (a stream as one object per line). Writes get a fresh mutation id unless `--mutation-id` is given. `--state` goes before or after the command. `meshctl help` lists the commands, `meshctl help <command>` its flags. Only `hook` and `version` are written by hand.

```bash
export AGENT_MESH_STATE=$state
daemon/bin/meshctl start-run --title demo
daemon/bin/meshctl spawn --run-id <run> --repo ~/projects/shop-api --slug fix-typo --task @task.md
daemon/bin/meshctl agents --run-id <run>
daemon/bin/meshctl send --to shop-api-fix-typo --type task --body "…"
daemon/bin/meshctl events --run-id <run>                 # follow; resume with --cursor '{"generation":…,"seq":…}'
```

An agent's own shell has `AGENT_MESH_TOKEN` and `AGENT_MESH_STATE`, so the same commands act as the agent (`meshctl inbox`, `meshctl send --to parent …`).

## Settings

The policy (`bin/mesh`'s `POLICY`, design §21) is host data, the same from every device and readable by the agents that run under it. `internal/settings/schema.go` is the one table: a leaf's key, type, default, summary, choices and whether it is read only at start. The settings screen is generated from it, and an app adds its own rows there (the desktop's `app.*`); it needs no action or event of its own. Only overrides are stored (the `settings` table, migration `0002`); a leaf nobody set is its default, so a new default reaches every host that never overrode it.

- `ListSettings {prefix}` returns `Setting`s: `key`, `value` (effective), `default`, `is_set`, `schema {type, summary, choices, restart}`, and who set it and when. Any actor class may call it. `meshctl settings --prefix tiers.claude.`.
- `SetSetting {meta, key, value}` and `ResetSetting {meta, key}` write: only a device or a root, idempotent like every write, and each emits a global `SettingChanged {key, value, previous, to_default}` with the actor and the mutation id. The event has no run, so every subscriber gets it, a run's agents included. A `Snapshot` doesn't carry settings: a client lists them after one, then follows the events. `meshctl set --key quota_stop --value 75`, `meshctl unset --key quota_stop`.
- A value is checked against its type: `string`, `strings`, `int`, `percent`, `bool`, `seconds`, `effort`, `chain`, `slots`, `kinds`, `mb_or_auto`, `json`. A failure is `InvalidArgument` naming the rule (`quota_stop must be a whole number 0 to 100`); a key no leaf has is `NotFound`.
- The daemon reads a leaf with `Daemon.Setting(reader, key)` (the override, else the default; a stored value the leaf's rule no longer takes is logged and the default used; a failed read is an error), so a change applies to the next read. A write that changes nothing (the same value again, a reset of a setting nobody set) emits no event. `seconds` is capped at 1e9 so a `time.Duration` can't overflow. Not ported yet, with the herdr-only leaves (views, `side_panes`, `root_reset.*`, `compact.*`, `claude.*`, `worker_cpus`, `worker_memory_high`): they wait for the switchover. `meshd` doesn't import `~/.config/agent-mesh.json`.

## Terminals

`mesh-term` owns the agents' PTYs, in a process of its own so a daemon restart leaves them running; at boot the daemon adopts what it finds (`AgentAdopted`), records exits that happened while it was down, marks an agent whose terminal is gone as `lost`, and never kills a terminal no agent claims.

- **Supervision.** In production both run as systemd user units (`packaging/systemd/`): `agent-mesh-term.service` holds the PTYs in its own cgroup, and `meshd --term-launch systemd` starts it when no host answers. Without systemd (and in dev and tests), `--term-launch detached` starts `mesh-term` in its own session; tests pass `--max-lifetime` so a killed test leaves nothing behind. One host per dir (a held lock), a token in `term/term.token`, and no pid is ever signalled without its start time matching.
- **Streams.** `OpenTerminal` gives a one-time ticket; the client opens `/v1/term/<agent>?ticket=…` on the daemon, which splices it to the host. Frames are `agentmesh.term.v1.TermFrame` (binary). The first client frame is `Attach`: `EXACT` (from an epoch and offset, falling back to a repaint marked `reanchored`), `TAIL` (mode preamble, then live) or `REPAINT` (preamble and the screen from the host's emulator, then live). The replay ends with `ReplayDone`; input sent before the client's `Ready` is dropped, so replayed queries draw no answers. While no client that can type is attached, the host's emulator answers terminal queries itself. The size is the smallest client's, clamped to 20-500 columns by 5-300 rows; only a client with input rights may resize after attaching; a resize moves the epoch. A client that falls behind is closed with code 4001 and reattaches by offset; the PTY is never paused.

## Agents and hooks

An agent starts with an allowlist of meshd's environment, not all of it: the shell basics (`HOME`, `PATH`, `LANG`, `TMPDIR`, `XDG_*`, `SSH_AUTH_SOCK`), what Claude Code needs to reach its model (`CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_*`, the proxy variables, the Bedrock and Vertex settings and credentials), a terminal, and its own identity. `meshd --agent-env KEY=VALUE` adds more, and `--cli claude=<path>` pins the binary; without it a bare `claude` is looked up on the agent's `PATH` by meshd, not on `mesh-term`'s. A meshd run by a systemd user unit has only what the unit sets, so put the login variables there (or in `--agent-env`).

`SpawnAgent` makes a worktree on `mesh/<run>/<slug>`, mints the agent's token (in `AGENT_MESH_TOKEN`, and in `<state>/agents/<id>/token` for its hooks), and starts its CLI through the adapter. Claude Code gets a `--session-id` and per-launch `--settings` hooks that run `meshctl hook claude --state <dir> --agent <id> <Event>`. Before the launch the worktree is trusted in Claude's global config (`projects[<worktree>].hasTrustDialogAccepted` in `$CLAUDE_CONFIG_DIR/.claude.json` or `~/.claude.json` of the agent's environment, written under the lock Claude takes, every other key kept; nothing when the worktree, its main checkout or a parent is trusted already, or the file doesn't exist): Claude shows its folder-trust dialog even under `--dangerously-skip-permissions`, fires no hook before it is answered, and its default answer is "No, exit". The launch also hooks `StopFailure`, which Claude fires on an API error instead of `Stop`: a `rate_limit` or `billing_error` whose message is a usage limit (`You've hit your session limit · resets 3pm (America/Sao_Paulo)`, `You're out of extra usage`) is `AGENT_STATE_LIMITED`, with the reset it names and whether it is the account's (session, weekly, usage, monthly spend: every model) or one model family's (`Opus limit`, `Sonnet limit`); any other failure (a capacity 429, a login error) is `AGENT_STATE_ERROR`. Antigravity (`agy`) resolves model+effort via `agy models` (never passing `--effort`), skips the folder-trust dialog with `--settings '{"trustedWorkspaces":[…]}'`, resolves an exact id named without an effort at its own effort (`DescribeModel`: `gemini-4-neon-low` runs as named), writes `.agents/hooks.json` into the worktree (a worker's repo's own committed hooks kept beside the mesh's when that version is on one of the repo's own refs, a local non-mesh branch or an origin branch; an asker's, a reviewer's or one from a fork's head replaced; kept out of git by `--skip-worktree` on a tracked file, else by a self-ignoring `.agents/.gitignore` in that worktree alone), enforces read-only and planning rules locally in `PreToolUse` (fail-closed, overriding `--dangerously-skip-permissions`: a payload it can't read whole is denied, and a session that isn't the agent's, its `$AGENT_MESH_AGENT` unset or another's, still has the rules checked but reports nothing), reports `PreToolUse` within a second without waiting on the spool lock (agy denies a tool whose hook outlives its timeout), becomes `IDLE` once its terminal has drawn and been quiet for `ReadySettle` (or 30 of them after its start, for one that never stops drawing), records its `conversationId` from its first prompt's hooks (with `LookupSession` falling back to the newest top-level conversation of its worktree in `conversation_summaries.db` or `history.jsonl` that isn't older than the agent, looked up only for an action that uses the id (a resume or a reopen) by an actor allowed to act on the agent, before that action's write, never inside it), reads a `Stop` with `continuationActive` as activity, not the turn's end, and maps `Stop` `ERROR` with `RESOURCE_EXHAUSTED` / 429 to `AGENT_STATE_LIMITED` (ready for `SwitchAgent --next` on `--conversation`) and any other to `AGENT_STATE_ERROR`; an agent at either is at its input box and takes reopens and idle retire as an idle one does, and at `ERROR` doorbells too (at `LIMITED` a doorbell's turn would fail on the same quota: its messages wait for the switch). The hook reads the daemon's address at call time and, when the daemon is down, spools to `<state>/spool/<agent>/`; the daemon drains the spool every few seconds. Hooks always exit 0 and print nothing (except an agy `PreToolUse` deny JSON; failures go to `<state>/hook.log`). The adapter turns each hook into neutral events and `reducer.Reduce` derives the state; a working agent, or one waiting on a prompt, that nothing was heard from for 10 minutes shows as unknown (Claude may fire no hook when a prompt is dismissed). A compaction remembers the state it interrupted and restores it when the compacted session starts (idle stays idle, mid-turn stays working); a resume's `SessionStart` does not make an agent idle. A spooled hook the daemon's drain gets an error for (not "unreachable") at least ten times over at least five minutes is dropped (kept as `.bad`, with a `HookDecodeFailed` event); the hook process's own drain never drops one; idempotency records of hooks are pruned after a day, others after two weeks. Messages are stored and announced by a one-line doorbell typed into the agent's terminal once it is idle and no client with input rights has typed in the last 15 seconds (it retries every 2 s); the agent reads them with `meshctl inbox`. An asker or reviewer (and a planner) launches with a `--disallowedTools` list (Claude: `Edit` rules, which Claude applies to every tool that edits files, `NotebookEdit` included, and prefix rules for `git push` and the gh writes) and `PreToolUse` deny flags (agy: paths and publish commands; Claude: publish commands only), which hold under `--dangerously-skip-permissions`. Claude's prefix rules miss `git -C . push` and the like, so its `PreToolUse` hook (`--deny-publish`) also checks every Bash command with agy's matcher, and a hook's denial is final in every permission mode (a hook that fails to run lets the tool through: the prefix rules stay as the backstop). The command check, for both CLIs, also unwraps `env`, `sudo`, `timeout`, `xargs` and the like, `sh -c` and `eval` strings, skips gh flag values (`gh pr --repo o/r merge`), and blocks `gh api` writes (a method other than GET, fields without one, a GraphQL mutation), and every gh command but an allowlist of reads (`pr list/view/diff/checks/status`, `issue list/view/status`, `release list/view/download`, `run view`, `search`, …: a gh command added later is denied until listed); it guards against an agent's mistake, not a determined one (a script it writes, a git alias).

## Same conversation: tiers, approve, switch, resume

A model change reopens the agent's own conversation (`claude --resume <session> --model … --effort …`), never a fresh agent briefed again, so it keeps its research (design §9, `bin/mesh`'s `swap_model`).

- **Tiers.** `SpawnAgent` takes a `tier` (`tiers.<kind>.<tier>` in the settings: the chain's first model at its effort) or a `model` the user named (at `effort`, else high). Neither is `InvalidArgument`: there is no default model, except for a root, whose model is the user's (it launches on the CLI's default unless one is named). A tier is checked whenever it is given. A named model leaves the agent no tier (the tier only gives the effort), so `next` is refused from it. A named model or effort with no plan phase is `pinned`.
- **Plan phase.** `plan` starts the agent `PLANNING`, a Claude agent under the same `--disallowedTools` list as a read-only one (`deny_edits`), optionally with a preset `exec_tier`. A `plan` sent by an agent with no phase that isn't pinned enters one, without a reopen (it plans on the model it is on, with no deny list).
- **`ApproveAgent`** (its parent or a device, only when its newest report since its last task or answer is a `plan`) stores the `approved` answer, sets `EXECUTING`, and reopens it on the execution tier (given, else the preset; or a named model) without the deny list. `keep_model` executes on the planning model; only the deny list goes, which is still a reopen. An agent with no plan phase is approved as it is. A task marked direct (it begins `Direct task`, as bin/mesh's does) sent with `SendMessage`, by the agent's parent or a device, ends a plan phase (the tier it runs on becomes the one `next` walks) and lifts a planner's deny list by a reopen on the same model, unless the role is read-only; any other task leaves a planner planning, under its list and with its preset execution tier; a `plan` from an agent that is executing, or has no phase and isn't pinned, enters the plan phase again, so its approval can name a tier.
- **`SwitchAgent`** moves it to a tier, a model, an effort alone, or `next`: the next model of its phase's tier chain (the quota move; never back to one before, and `FailedPrecondition` at the chain's end). It stores an `info` telling the agent where it is now (not a task: a planner switched before approval is still approved on its plan). A switch to a named model leaves the phase no tier, so `next` is refused from it rather than going back to the chain's first model. A model at a usage limit is remembered (in memory: until the reset the CLI named, else `limits.hold` seconds; an account-wide limit holds every model of the CLI), and the chain is walked past it: a new agent, an approve and a switch to a tier take the first model with quota left (all held: the one freed first), and `next` the first free one after the agent's own (none free: the next one).
- **`ApproveAgent` on a stopped agent** is refused: approving never undoes a stop; resume it (it comes back planning), then approve.
- **Usage limits** (`limits.auto`, default `switch`; `limits.hold`): a pass every few seconds looks at each agent at `LIMITED` that isn't a root (its model is the user's) and has no reopen pending. With `switch`, a limit on the agent's own model moves it to the next model of its phase's chain that has quota left (a reopen, `why` `quota`, with an `info` saying so); with `switch` or `continue`, once the limit is over (the reset it named, else `limits.hold` seconds after it was seen; a limit found after a restart is held that long from then) it reopens the agent on the same model with an `info` to carry on (`why` `limit reset`). An account-wide limit walks no chain (every model shares it), and nothing is done when no model of the chain is free before the reset. `off` leaves it to the root or the user (`SwitchAgent next`).
- **`ResumeAgent`** reopens a stopped agent: with a task it plans (`plan`, on the tier or model given: the tier it had may be the execution tier's), a direct task, or as it was.
- **The reopen.** Each of these stores a `Reopen` on the agent (`pending_reopen`, event `AgentReopenRequested`); a newer request replaces one not done yet. It runs when the agent is idle or stopped and no client with input rights is typing, else at its next `IDLE`, before any doorbell: the old process is stopped (SIGTERM, then SIGKILL), its exit is not recorded as one, a new token is minted, and the conversation is relaunched in a new terminal labelled with the reopen's id (`AgentReopened`). The agent keeps its id, name, worktree and session; the message the action stored rings in the new process. A pending reopen survives a meshd restart; a terminal a reopen had started when meshd died is found by its label and recorded, never launched twice. `StopAgent` drops a pending reopen (`AgentReopenDropped`); a relaunch that fails leaves the agent `EXITED`, for `ResumeAgent` to try again.

## Retire, stop, caps

- **Retire** (design §18). `RetireAgent` (its parent or a device) stops an agent's process on purpose and keeps its conversation: state `RETIRED`, token revoked, worktree and branch kept, terminal acknowledged; no `AgentExited`. A pending reopen is dropped. Anything its dying process or its spool still says is ignored. `ResumeAgent`, or a message, brings it back.
- **A message to a stopped agent** (`RETIRED`, or `EXITED` with a session) stores the message and requests the reopen in the same write: a `task` marked direct (it begins `Direct task`) resumes it direct, as one sent to a live agent is (it ends a plan phase and drops the planning deny list), any other task brings it back as it was (a planner still planning); for a task it plans on a tier use `ResumeAgent` with `plan`, an `answer` or `question` brings it back as it was. An `info` is only stored; it is read when the agent is next resumed. The response's `resumed` is the reopen. The message is stored in any case: when the resume is refused (the cap, the memory floor, a closed run, no conversation to resume) the agent stays stopped and the response's `resume_error` says why, so a report to a retired parent is never lost to the cap. Nothing is queued: the launch is not retried.
- **Idle retire.** A pass every `RetireEvery` (10 s) retires an agent that is IDLE, whose newest report since its last task or answer is a `done` or `failed`, and that stayed idle `idle_retire` seconds (0 never) since the later of that report and its last activity. Not a root; not one with a reopen pending, unread mail (work is coming, or a doorbell was lost), a `plan` or `question` waiting on its parent, or a client with input rights attached to its terminal (someone is looking). The check is repeated under the agent's lock inside the retiring write, so a message that arrives meanwhile either keeps it open or finds it retired and resumes it.
- **`StopRun`** (a device) retires every agent of a run and closes it (`RunStopped`); nothing starts or resumes in a closed run. A clean worktree is then removed, and its branch with it unless the branch moved past the commit it started at (`Agent.base_commit`, so a branch another one stacks on still counts), or has a remote branch of its name (a branch started from `origin/main` has an upstream for free: that is not work); a worktree with uncommitted changes stays, with its branch. An agent spawned while it runs is retired too, a pending resume on a stopped agent is dropped, and the processes are stopped together (one `StopWait` at most, not one per agent). The response says what happened to each.
- **`caps.agents`** (default 8; 0 no cap) limits agent processes on the host: starting, running, or a stopped agent whose resume is pending. A spawn or a `ResumeAgent` past it is `ResourceExhausted` (a message that would resume one is stored with `resume_error`), checked inside the write that stores the agent or the reopen, where the one writer makes the count and the record one step, so a burst of spawns can't all pass. A switch or approve replaces a process and is never refused, and neither is the reopen a `Direct task` to a running planner requests to lift its deny list: each swaps one process for one, though the old one counts alongside the new until it exits. A direct task to a stopped agent is a resume and is refused like any (it stays as it was, planning).
- **The memory guard** (design §17) runs in the same places: refused (`ResourceExhausted`) while memory plus swap free is under `min_free_mb` (`auto`: 10% of RAM plus 10% of swap plus 1 GB, at least 2 GB; 0 off) or `/proc/pressure/memory`'s `full avg60` is over `memory_pressure_max` (0 off). A launch that passes counts 400 MB used for 2 minutes, under its agent's id (a launch that fails gives it back), so four spawns in a row don't read the same free memory. `MeminfoPath` and `PressurePath` of the agent config point it at other files (tests); without them it reads `/proc`, and where there's no `/proc` it refuses nothing. The sweep of leftover processes in a worktree (`sweep_worktrees`) and the CPU and memory scopes (`worker_cpus`, `worker_memory_high`) are not ported.

## Delivery tests and hook fixtures

- **Delivery** (`internal/daemon/delivery_test.go`), the two bugs of the herdr mesh: every type of report (and an `info`) reaches the root and rings its doorbell, a `wait` is stored for it and rings none (it asks nothing of the root; stored as delivered), one sent while the root is mid-turn is stored and rung at its next IDLE (never typed into the turn), and a `plan` from a worker resumed into planning reaches the root and is approved; and a fresh pane's input-box placeholder never holds a doorbell. The daemon judges typing by client input (`input_clients`, `last_client_input`), not by the screen: the fake claude draws Claude Code's placeholder (`FAKECLAUDE_PLACEHOLDER`), nobody types, and the doorbell rings at once. Each adapter gets these two tests as it lands.
- **Real hook payloads.** `internal/adapter/claude/testdata/<version>/` holds the scrubbed payloads of a real Claude Code session, numbered in the order they fired, with `sequence.json` naming each scenario (startup, tool calls, permission prompts, `/compact`, `/clear`, a reopen, `/exit`). `fixtures_test.go` decodes every fixture of every version, replays the session through the reducer, and fails when `VerifiedVersions` and `testdata` disagree. `scripts/capture-claude-hooks.sh` makes them: **by hand only**, never from a test or CI. It runs the real `claude` through its own meshd and mesh-term on a temp state dir, in a temp git repo, for a few short turns on the light tier (the account's usage, and a transcript under `~/.claude/projects/`; Claude also records the temp folder as trusted in `~/.claude.json`); `meshctl hook` saves each raw payload when `$AGENT_MESH_HOOK_CAPTURE` is set, and `internal/testutil/capturehooks` drives the session and scrubs the payloads (home, repo and temp paths, session ids as stable stand-ins, a compaction's model-written summary dropped; a user or host name or an email left over is an error). Hooks fired in the same instant (a stopped process's `SessionEnd` beside the new `SessionStart`) are ordered by the time each hook was called, so a re-capture can swap two of them. Read the fixtures' diff before committing them.
- What the real session showed (2.1.332): the permission prompt is `Notification` with `notification_type: "permission_prompt"`; `/compact` fires `PreCompact`, a `SubagentStop` of the compaction's own subagent, then `SessionStart` with source `compact`; `/clear` ends the session with reason `clear` and starts a new id; and `claude --resume <id>` **keeps the session id**: the stopped process's `SessionEnd` (reason `other`) arrives first, then `SessionStart` with source `resume`, under the same id, so a reopen's record of the conversation stays valid.

## Protocol notes

- **Writes** carry `RequestMeta`: a repeated `mutation_id` returns the first response without running again, and a write past `expires_at` is refused. Events a write causes carry its mutation id.
- **Events** have a `seq` and the log's `generation`. `SubscribeEvents` with a cursor of the same generation resumes (`Resumed`, then the backlog, then live); anything else starts with a `Snapshot`. Only an `End` frame ends a stream on purpose; after any other close, resubscribe from the last cursor. A subscriber more than `events.LiveBuffer` events behind is dropped (`resource_exhausted`) and resumes the same way.
- **What waits on the user:** `ListWaiting {run_id}` returns `Waiting {kind, run_id, agent_id, message, detail}` rows, oldest first, plans and questions before prompts (`internal/daemon/waiting.go`; `meshctl waiting`). A row is a PLAN or QUESTION sent to an open run's lead (its first root) that no later ANSWER to its author followed, unless the author exited (a retired one is woken by the answer, so it counts); or an agent shown as NEEDS_INPUT (a prompt left unanswered past the unknown threshold shows as unknown and drops out). A device or read-only device reads every open run; a lead reads its own run's, and a worker is refused. Read-only: no event, so a client re-lists after the events that change it (a message, a state change, an exit, a retire, a stopped run).
